The elliptic curve method

The elliptic curve method

Pollard's \(p - 1\) method finds a prime factor when one particular number happens to be smooth. Lenstra's idea was to replace that one number by the orders of as many groups as you care to try: an elliptic curve for each attempt. It finds factors of twenty and more digits whatever the size of the number they divide.

From p − 1 to curves

The \(p - 1\) method computes \(a^M \bmod n\) for \(M\) a product of small prime powers. If \(p \mid n\) and \(p - 1\) divides \(M\), then \(a^M \equiv 1 \pmod p\), and \(\gcd(a^M - 1, n)\) reveals \(p\). It works in the group \((\mathbb{Z}/p)^*\), of order \(p - 1\), and if \(p - 1\) has a large prime factor there is nothing to be done: there is only one such group.

An elliptic curve modulo \(n\) is, modulo each prime \(p \mid n\), a group \(E(\mathbb{F}_p)\) whose order is somewhere in the Hasse interval \([p + 1 - 2\sqrt p,\ p + 1 + 2\sqrt p]\), and different curves give different orders, spread over that interval. Compute \(M \cdot P\) on the curve modulo \(n\). If the order of \(E(\mathbb{F}_p)\) divides \(M\), the result is the point at infinity modulo \(p\) but (almost always) not modulo the other primes, and a gcd with \(n\) gives \(p\). If the curve is unlucky, take another.

import { ecm, ecmCurve, factor, formatFactors } from "@ratmath/numtheory";

const F7 = 2n ** 128n + 1n;
ecm(F7);                                  // 59649589127497217n
ecm(F7, { details: true });               // { factor: 59649589127497217n, stage: 2, sigma: 26n, B1: 2000, B2: 200000 }
formatFactors(factor(F7));                // "59649589127497217 · 5704689200685129054721", both proven prime

The seventh Fermat number was first factored in 1970 by Morrison and Brillhart, with the continued fraction method on an IBM mainframe. Here the twenty-first curve tried finds the 17-digit factor in a fraction of a second. Pollard's rho would need about \(\sqrt{6\cdot10^{16}} \approx 2\cdot10^8\) steps, and \(p - 1\) fails because \(p - 1 = 2^9 \cdot 116503103764643\).

Why that curve worked

The curve with \(\sigma = 26\), taken modulo \(p = 59649589127497217\), has

\[ 59649589504338456 = 2^3 \cdot 3 \cdot 7 \cdot 67 \cdot 233 \cdot 331 \cdot 599 \cdot 114713 \]

points. Every prime power in it is below \(B_1 = 2000\) except one prime, 114713, which is below \(B_2 = 200000\). That is exactly the pattern the two stages look for. Stage 1 multiplies the starting point by every prime power up to \(B_1\). Stage 2 then allows for one more prime \(q\) between \(B_1\) and \(B_2\): instead of multiplying by each \(q\) in turn, it compares the x-coordinates of a few hundred precomputed multiples, which costs two multiplications per prime. The curves

Curves are in Montgomery form \(By^2 = x^3 + Ax^2 + x\), where a point can be doubled, and two points added when their difference is known, using x-coordinates only and no divisions. Suyama's parametrisation produces from a number \(\sigma \ge 6\) a curve and a point on it, with group order divisible by 12, which makes smoothness a little more likely. ecm tries \(\sigma = 6, 7, 8, \dots\), so a run is reproducible, and ecmCurve(n, sigma, { B1, B2 }) runs a single curve.

Inside factor

factor now runs trial division, a short Pollard rho, \(p - 1\), and then the elliptic curve method with growing bounds (\(B_1\) = 2000, 11000, 50000) before it gives up. Option effort multiplies the number of curves at each level. What comes out is still checked: each prime factor is proven, by Baillie–PSW below \(2^{64}\) and by a certificate above.

formatFactors(factor(10n ** 40n + 1n));   // "17 · 5070721 · 5882353 · 19721061166646717498359681"
formatFactors(factor(2n ** 137n - 1n));   // "32032215596496435569 · 5439042183600204290159"

A failure is not a proof of anything: when no factor is found, the remaining number may be a product of two primes of thirty digits each, and factor refuses with the code "too-hard". Numbers like that need the quadratic or number field sieve, which are not in this library.
