Congruences

Congruences

Arithmetic modulo m: when a·x ≡ b has solutions and how many, gluing congruences together with the Chinese remainder theorem, roots of polynomials modulo any m, and the cyclic groups that make discrete logarithms possible.

Linear congruences

import { solveLinear, crt, rootsMod, hensel, primitiveRootMod, discreteLog } from "@ratmath/numtheory";

solveLinear(6, 4, 10);   // { solutions: [4n, 9n], modulus: 10n, g: 2n, reduced: { x: 4n, modulus: 5n } }
solveLinear(6, 5, 10);   // { solutions: [], g: 2n, reason: "gcd(6, 10) = 2 does not divide 5" }

\(ax \equiv b \pmod m\) is solvable exactly when \(g = \gcd(a, m)\) divides \(b\). Then dividing through gives \((a/g)x \equiv b/g \pmod{m/g}\), where \(a/g\) is invertible, so there is one solution modulo \(m/g\) and \(g\) of them modulo \(m\). The inverse comes from the extended Euclidean algorithm: \(as + mt = g\).

The Chinese remainder theorem, for any moduli

crt([2, 3, 2], [3, 5, 7]);   // { x: 23n, modulus: 105n }: Sunzi's problem
crt([1, 3], [4, 6]);          // { x: 9n, modulus: 12n }: moduli need not be coprime
crt([1, 2], [4, 6]);          // null: x odd and x even at once
solveLinearSystem([[2, 1, 5], [3, 2, 7]]);   // 2x ≡ 1 (mod 5), 3x ≡ 2 (mod 7): { x: 3n, modulus: 35n }

Two congruences \(x \equiv r_1 \pmod{m_1}\), \(x \equiv r_2 \pmod{m_2}\) are compatible exactly when \(r_1 \equiv r_2 \pmod{\gcd(m_1, m_2)}\), and then they have one solution modulo \(\operatorname{lcm}(m_1, m_2)\). Combining two at a time handles any list.

Polynomial congruences and Hensel's lemma

To solve \(f(x) \equiv 0 \pmod m\), solve modulo each prime power in \(m\) and glue with the Chinese remainder theorem. Modulo \(p\), try every residue (or factor, for large \(p\)). To go from \(p^k\) to \(p^{k+1}\): if \(f(r) \equiv 0 \pmod{p^k}\) and \(f'(r) \not\equiv 0 \pmod p\), then

\[ r' = r - \frac{f(r)}{f'(r)} \pmod{p^{k+1}} \]

is the unique lift, Newton's method with \(p\)-adic convergence. When \(f'(r) \equiv 0\) a root may lift to many or none; rootsMod then tries every lift.

rootsMod([1, 0, 1], 65);       // x² + 1 ≡ 0 (mod 65): [8n, 18n, 47n, 57n]
rootsMod([-1, 0, 1], 8);       // x² ≡ 1 (mod 8): [1n, 3n, 5n, 7n], four roots, not two
hensel([1, 0, 1], 2, 5, 4);    // the root ≡ 2 of x² + 1 lifted to mod 625: 182n

Primitive roots and indices

The units modulo \(n\) form a cyclic group exactly when \(n\) is \(1, 2, 4, p^k\) or \(2p^k\) for an odd prime \(p\) (Gauss). A generator is a primitive root; \(g\) is one exactly when \(g^{\varphi(n)/q} \not\equiv 1\) for every prime \(q \mid \varphi(n)\). Then each unit \(h\) is \(g^x\) for one \(x\) modulo \(\varphi(n)\), its index or discrete logarithm, found by baby-step giant-step in about \(\sqrt n\) steps.

primitiveRootMod(25);    // 2n
primitiveRootMod(8);     // null: (Z/8)ˣ is {1, 3, 5, 7}, every element squares to 1
order(10, 13);           // 6n: 1/13 has a period of 6 decimal digits
discreteLog(3, 13, 17);  // 4n: 3⁴ = 81 ≡ 13 (mod 17)
discreteLog(2, 3, 7);    // null: 2 generates only {1, 2, 4}
