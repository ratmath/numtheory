The elliptic curve method

Pollard's p−1p - 1p−1 method finds a prime factor when one particular number happens to be smooth. Lenstra's idea was to replace that one number by the orders of as many groups as you care to try: an elliptic curve for each attempt. It finds factors of twenty and more digits whatever the size of the number they divide.

From p − 1 to curves

The p−1p - 1p−1 method computes aM mod na^M \bmod naMmodn for MMM a product of small prime powers. If p∣np \mid np∣n and p−1p - 1p−1 divides MMM, then aM≡1(modp)a^M \equiv 1 \pmod paM≡1(modp), and gcd⁡(aM−1,n)\gcd(a^M - 1, n)gcd(aM−1,n) reveals ppp. It works in the group (Z/p)∗(\mathbb{Z}/p)^*(Z/p)∗, of order p−1p - 1p−1, and if p−1p - 1p−1 has a large prime factor there is nothing to be done: there is only one such group.

An elliptic curve modulo nnn is, modulo each prime p∣np \mid np∣n, a group E(Fp)E(\mathbb{F}_p)E(Fp​) whose order is somewhere in the Hasse interval [p+1−2p, p+1+2p][p + 1 - 2\sqrt p,\ p + 1 + 2\sqrt p][p+1−2p​, p+1+2p​], and different curves give different orders, spread over that interval. Compute M⋅PM \cdot PM⋅P on the curve modulo nnn. If the order of E(Fp)E(\mathbb{F}_p)E(Fp​) divides MMM, the result is the point at infinity modulo ppp but (almost always) not modulo the other primes, and a gcd with nnn gives ppp. If the curve is unlucky, take another.

import { ecm, ecmCurve, factor, formatFactors } from "@ratmath/numtheory";

const F7 = 2n ** 128n + 1n;
ecm(F7);                                  // 59649589127497217n
ecm(F7, { details: true });               // { factor: 59649589127497217n, stage: 2, sigma: 26n, B1: 2000, B2: 200000 }
formatFactors(factor(F7));                // "59649589127497217 · 5704689200685129054721", both proven prime

The seventh Fermat number was first factored in 1970 by Morrison and Brillhart, with the continued fraction method on an IBM mainframe. Here the twenty-first curve tried finds the 17-digit factor in a fraction of a second. Pollard's rho would need about 6⋅1016≈2⋅108\sqrt{6\cdot10^{16}} \approx 2\cdot10^86⋅1016​≈2⋅108 steps, and p−1p - 1p−1 fails because p−1=29⋅116503103764643p - 1 = 2^9 \cdot 116503103764643p−1=29⋅116503103764643.

The curves

Curves are in Montgomery form By2=x3+Ax2+xBy^2 = x^3 + Ax^2 + xBy2=x3+Ax2+x, where a point can be doubled, and two points added when their difference is known, using x-coordinates only and no divisions. Suyama's parametrisation produces from a number σ≥6\sigma \ge 6σ≥6 a curve and a point on it, with group order divisible by 12, which makes smoothness a little more likely. ecm tries σ=6,7,8,…\sigma = 6, 7, 8, \dotsσ=6,7,8,…, so a run is reproducible, and ecmCurve(n, sigma, { B1, B2 }) runs a single curve.

Inside factor

factor now runs trial division, a short Pollard rho, p−1p - 1p−1, and then the elliptic curve method with growing bounds (B1B_1B1​ = 2000, 11000, 50000) before it gives up. Option effort multiplies the number of curves at each level. What comes out is still checked: each prime factor is proven, by Baillie–PSW below 2642^{64}264 and by a certificate above.

formatFactors(factor(10n ** 40n + 1n));   // "17 · 5070721 · 5882353 · 19721061166646717498359681"
formatFactors(factor(2n ** 137n - 1n));   // "32032215596496435569 · 5439042183600204290159"

A failure is not a proof of anything: when no factor is found, the remaining number may be a product of two primes of thirty digits each, and factor refuses with the code "too-hard". Numbers like that need the quadratic or number field sieve, which are not in this library.
