Counting points

Over the field of ppp elements a curve has finitely many points, and they still form a group. How many there are is the question behind elliptic curve cryptography, factoring and primality proving. Three methods, each faster and subtler than the last, and each a proof.

A curve over Fp

import { ellipticCurve } from "@ratmath/numtheory";

const C = ellipticCurve([2, 3], { mod: 97 });   // y² = x³ + 2x + 3 over F_97
C.count();            // 100n, counting the point at infinity
C.trace();            // -2n: #E = p + 1 − t
C.points().length;    // 99
C.liftX(3);           // [(3, 6), (3, 91)]
const P = C.point(3, 6);
C.add(P, P);          // (80, 10)
C.order(P);           // 5n
C.structure();        // { order: 100n, structure: [2n, 50n] }: the group is Z/2 × Z/50

Coordinates are BigInt residues. The modulus must be prime (proven: above 2642^{64}264 a certificate is found first). Every Weierstrass form works, including p=2p = 2p=2 and p=3p = 3p=3, where the short form does not exist. A curve over Q\mathbb{Q}Q reduces with curve.modulo(p).

Hasse's theorem

About half of the xxx give a square on the right-hand side and so two points, which suggests about p+1p + 1p+1 points in all. Hasse proved the error is small:

#E(Fp)=p+1−t,∣t∣≤2p. \#E(\mathbb{F}_p) = p + 1 - t, \qquad |t| \le 2\sqrt p. #E(Fp​)=p+1−t,∣t∣≤2p​.

Three ways to count

const B = ellipticCurve([2, 3], { mod: 1000003 });
B.count({ method: "naive" });    // 999708n
B.count({ method: "bsgs" });     // 999708n
B.count({ method: "schoof" });   // 999708n

The character sum. #E=p+1+∑xχ(x3+ax+b)\#E = p + 1 + \sum_x \chi(x^3 + ax + b)#E=p+1+∑x​χ(x3+ax+b), where χ\chiχ is the Legendre symbol. One table of squares and one pass over xxx: about ppp steps, fine up to a few million.

Baby steps and giant steps. The order of any point PPP divides #E\#E#E, and #E\#E#E lies in the Hasse interval, which has length 4p4\sqrt p4p​. Shanks's method finds a multiple of the order of PPP inside that interval in about p1/4p^{1/4}p1/4 steps: store jPjPjP for small jjj and stride through the interval. From the multiple, the exact order follows by removing primes. One point may not settle it, because several multiples of its order can fit in the interval. Mestre's remedy is to work on the curve and on its quadratic twist together (their counts add up to 2p+22p + 22p+2): he showed that for p>229p > 229p>229 one of the two has a point whose order has a single multiple in the interval. The count is accepted only when that uniqueness has been checked, so it is a proof.

Schoof's algorithm. Polynomial in log⁡p\log plogp. For a small prime lll, the equation φ2−tφ+p=0\varphi^2 - t\varphi + p = 0φ2−tφ+p=0 is tested on the points of order lll: t mod lt \bmod ltmodl is the one τ\tauτ for which

φ2(P)+[p mod l] P=[τ] φ(P)for every P of order l. \varphi^2(P) + [p \bmod l]\,P = [\tau]\,\varphi(P) \quad\text{for every } P \text{ of order } l. φ2(P)+[pmodl]P=[τ]φ(P)for every P of order l.

The points of order lll are never found. They are the roots of the division polynomial ψl\psi_lψl​, of degree (l2−1)/2(l^2 - 1)/2(l2−1)/2, and all of them are handled at once by computing with polynomials modulo ψl\psi_lψl​ and the curve equation. Enough primes lll, with product above 4p4\sqrt p4p​, determine ttt by the Chinese remainder theorem.

One subtlety: ψl\psi_lψl​ need not be irreducible, so a division modulo it can fail. When it does, the failure hands over a factor of ψl\psi_lψl​, and the computation is repeated modulo the factor; any factor will do, because the equation holds at every point of order lll.

With method: "auto" (the default) the character sum is used below 2222^{22}222, baby steps and giant steps below 2722^{72}272, and Schoof above. The implementation of Schoof here uses schoolbook polynomial arithmetic and is meant to be read: it takes about a second at p≈1012p \approx 10^{12}p≈1012 and grows quickly from there. The Elkies and Atkin improvements that make it fast for cryptographic sizes are not here.

Division polynomials

C.divisionPolynomial(3);   // [93n, 36n, 12n, 0n, 3n]: 3x⁴ + 12x² + 36x + 93 = 3x⁴ + 6ax² + 12bx − a² mod 97

The roots of the nnn-th division polynomial are the x-coordinates of the points P≠OP \ne OP=O with nP=OnP = OnP=O. For even nnn the full ψn\psi_nψn​ is 2y2y2y times the polynomial returned, the factor yyy accounting for the points of order 2.

A key exchange

In a group where multiplying is easy and undoing it is hard, two people can agree on a secret in public: each picks a secret number, publishes that multiple of a base point, and multiplies the other's point by their own number. With toy sizes it looks like this; real curves have about 22562^{256}2256 points and standardised parameters, and real implementations must also resist timing attacks, which this code does not try to do.
